# Export Templates

Godot Launcher keeps export templates in shared storage so projects can reuse them while keeping their editor settings separate. Open **Export Templates** in the sidebar to manage two kinds of collections:

- **Official** collections contain files for a Godot version and edition. Projects using Official share the same collection.
- **Imported** builds contain complete TPZ packages in a central library. Give each build a name and select it for the projects that need it.

Multiple imported builds can use the same Godot version and edition. Importing a build does not change any project's saved selection.

:::info Installed files and platform coverage

Sizes and file counts describe the files currently present, including files installed through Godot and system metadata. Platform badges are inferred from filenames; they do not guarantee that every template for that platform is installed. An Official collection can contain only the files you need, and you can add more later.

:::

## Download official export templates

1. Choose **Download templates** and select a Godot version and edition. Use the channel and installed-editor filters to find the release.
2. Select the template files you need. Review the files to add or remove.
3. Choose **Save changes**. You can also open **Manage templates** on an existing collection to change its installed files.

Standard and .NET collections are separate. Templates for one version and edition do not supply another. For Godot's export presets and platform requirements, see [Exporting projects](https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html).

:::warning Shared changes affect other projects

Adding or removing Official files affects every project using that version and edition's Official collection, including Godot editors opened outside Godot Launcher. This also applies when you manage Official files from **Project Settings > Export Templates**.

:::

## Import a named build

1. Choose **Import .tpz**, then **Choose TPZ file**.
2. Select the package and choose **Next**. Godot Launcher checks it and shows its version, edition, platform badges and file count.
3. Enter a **Name**, such as `Cloud Build`, then choose **Save**.

The original archive stays where it is. The imported files appear as a named build in the **Imported** section. Use its folder action to view the files.

:::warning Use a trusted package source

Package checks do not establish who created a build or whether it supports encryption or another custom capability. The build name is your description. Import packages from a source you trust.

:::

Imported builds are managed as complete packages. Their individual files cannot be added or removed through Godot Launcher. Use **Replace TPZ** to change the package.

## Select a project's build

Open **Project Settings > Export Templates** and choose an **Export template build** for the selected Godot version and edition:

| Selection | Behaviour |
| --- | --- |
| **Official** | Uses the shared Official collection. This is the initial choice. |
| A named imported build | Uses that matching entry in the central library. |

Choose **Update** to save. Orange indicators mark pending changes. Closing the drawer with unsaved changes offers to discard them or go back.

Selecting an import changes the project's connection to template files; it does not copy the package into the project. Switching back to **Official** uses the shared collection again. If the project still has local templates awaiting migration, complete the migration review first.

:::info Choices stay on this computer

Build choices are saved separately for each Godot version and edition. They are not included in the project's portable `.godotlauncher` metadata. Custom editor environments are managed separately; manage their export templates in Godot.

:::

### When a selected build is unavailable

A build with missing files is marked **Unavailable** and cannot be selected. If it was already selected, its name stays visible with a warning. Godot Launcher does not silently switch the project to Official.

Choose **Open Export Templates**, then **Replace TPZ** on the build to restore its package. Alternatively, choose another matching build or **Official** in Project Settings and select **Update**. If Official has no templates for that version yet, download the required files before exporting.

Availability is checked again when you save a changed build selection. If files have disappeared since you opened Settings, the selection remains visible with the warning so you can resolve it.

## Connect existing projects

Empty official editor environments connect automatically. Projects with existing local export template files need a migration decision. Open **Migrate projects** from Export Templates and review the project and its versions.

| Choice | What happens |
| --- | --- |
| **Switch to shared export templates** | Adds missing filenames to the shared collection, keeping the shared copy when a filename already exists. The project then uses shared templates. |
| **Delete local export templates and use shared** | Removes the local files without adding them to shared storage. The project uses Official, even if its version has no templates installed yet. |
| **Save as imported templates** | Saves each local version as a named imported package and uses the matching import for the project. Shared Official files stay unchanged. |

:::warning Review custom templates before migrating

A folder's location or matching filenames do not prove that its files are official. Use **Save as imported templates** when you need to preserve a custom package independently of the shared collection.

After a successful migration, the original local files are removed. No backup is retained. Keep your own copy if you may need it later.

:::

Use **Finish later** to leave undecided projects pending and return to them from Export Templates. If an operation fails, review its result before retrying: files already added to the shared collection can remain there while the project's original local files are retained.

## Rename, replace or delete an import

Use **Rename** to change a build's name and folder name. Saved project selections continue to refer to that build.

Use **Replace TPZ** to replace the whole package. The replacement must have the same Godot version and edition. Projects using the build will use its replacement files.

Use **Delete imported build** to remove a package. If projects use it now or remember it for another editor version, the confirmation lists those references. Choose a matching replacement or **Official**, then choose **Switch and delete**. Only the affected version's saved choice changes.

:::warning Close editors and keep any backups you need

Close affected Godot editors and stop exports before changing connections, replacing packages or deleting templates. Deletion is permanent and no backup is kept. Other tools can still change the files while a template operation is running.

:::

## Move template storage

Open **Settings > Export Templates** to see the locations for **Official export templates** and **Imported custom templates**. You can move either collection independently.

1. Close Godot editors and stop exports.
2. Choose **Move** beside the collection, then select an empty, writable destination folder outside the existing template storage folders.
3. Review the destination, data size and available space.
4. Choose **Move templates** and keep Godot Launcher open until the move finishes.

:::info Godot's default path stays the same

Moving Official storage keeps a connection at Godot's default template path. Project connections are updated as part of the move. Open projects through Godot Launcher to keep using their saved template choices.

Use **Move back to Godot's default location** to return relocated Official files. Changing the editor install location does not move template storage.

:::

You can cancel while the move offers **Cancel**. If the selected drive is unavailable, reconnect it and retry. If an interrupted move requires recovery, close Godot and use **Recover files** before trying another move. For other storage errors, check the reported location and permissions before retrying.

## Refresh and recover

Use **Refresh** after external file changes. If an interrupted template operation needs attention, close Godot and use **Recover files**. If recovery cannot finish because files have changed or a drive is missing, restore access and inspect the reported folders before retrying.

See [Storage Paths and Files](../reference/storage-paths.md#shared-export-templates) for default locations and [Editor Settings Per Project](./editor-settings.mdx) for editor settings.
