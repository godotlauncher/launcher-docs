# Install a Godot Editor {#installing-a-godot-editor}

In **Godot Launcher**, you can install an official editor from **Installs**, register a custom-built editor, or choose an official editor to download while creating a project.

## Install an official Godot editor

1. Go to **Installs** from the left-hand navigation menu.
2. Click **Install Editor**.
3. Choose **Latest** for recent releases or **All** to find an older version.
4. Choose **Stable** or **Prerelease**.
5. Find the release you need and select **Standard** or **.NET**.
6. Wait for the installation to finish. The editor appears in **Installs** and can be selected for projects.

Use **Reload Release List** to check for newly published releases. You can install multiple releases side by side.

## Choose Standard or .NET

- **Standard** is the usual choice for GDScript projects.
- **.NET** is required for projects that use C#.

If you are not sure, choose **Standard**. You can install both variants of the same release.

Godot Launcher works with Godot 4 and newer editor builds.

:::info C# requires the .NET SDK
To use C# in your project, install the **.NET SDK** from the [Microsoft .NET website](https://dotnet.microsoft.com/download) as well as a .NET-enabled Godot editor. See the [Godot Engine C# documentation](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/index.html) for current requirements.
:::

## Cancel an editor download

The drawer shows queued, download, and installation progress. You can close it
while an installation continues. Select **Cancel editor download**, the X beside
its progress, in **Installs** to stop a queued, preparing, or downloading editor
and remove its partial download. This also works for downloads started by a
project.

Cancellation is unavailable after extraction starts. If several projects are
waiting for the same editor version and edition, cancelling stops that shared
download for all of them. Other editor downloads continue.

Projects already added to the launcher stay listed with a missing editor.
Select **Install required editor** to try again. Cancelling during Create Project
returns to the filled form without creating a project.

If a download or archive check fails, the editor is not installed. See [editor installation troubleshooting](../troubleshooting.md#godot-editor-installation-and-availability) for recovery steps.

## Manage installed editors

The **Installs** view groups official and custom editors by Godot version. Standard, .NET, prerelease, and custom entries remain distinct within those groups.

- If an official editor becomes unavailable, select **Retry** after restoring its folder or **Reinstall** to download the same release and variant from the editor catalogue. Projects that used the unavailable editor are repaired to use the recovered installation.
- If a custom editor becomes unavailable, restore its manifest and editor paths, then select **Retry**. The launcher does not download custom builds.
- Select **Delete Release from This Device** beside an official editor, then confirm with **Remove** to delete its installation.
- Change the download location from [editor install location settings](../settings/editor-installs-location.mdx).

Removing an editor does not delete your projects. See [Troubleshooting](../troubleshooting.md#godot-editor-installation-and-availability) if an installation or saved editor location is unavailable.

### Remove several editors

Use multi-select in **Installs** to remove several editors with one confirmation.

1. Select **Enable multi-select**, the checklist icon at the left of the toolbar.
2. Tick the editors to remove, or open **Actions > Select unused editors**.
3. Select **Actions > Remove selected**.
4. Check the editor list and any projects shown in **Remove selected editors**, then select **Remove selected** to confirm.

**Select unused editors** selects launcher-managed editors with no assigned projects. Projects with unavailable files still count as using their assigned editor. Custom editors are excluded from this action; select them individually or use **Select all** to include them.

Search filters the visible rows without clearing your selection. **Clear selection** unticks all editors. **Disable multi-select** also clears the selection and restores the individual editor buttons. Editors with an install or another action in progress cannot be selected.

:::warning Projects using a selected editor
Removing an installed editor deletes its editor files. Projects assigned to it need another editor before they can launch. Removing a custom editor unregisters it from Godot Launcher and keeps its files. Your project files are kept in both cases.
:::

The launcher checks each editor again before removal. An editor selected with **Select unused editors** is kept if a project starts using it. Changed or busy editors are also kept. If a removal fails, the dialog shows the result for each editor; resolve the reported problem and use **Retry failed removals**. Successful removals stay removed.

## Use Godot from a terminal

Choose one installed editor as the default for the `godot` command. This works
with official editors and registered custom builds on Windows, macOS, and Linux.
Setup applies to your user account and does not require administrator permissions.

1. In **Installs**, select the terminal icon button beside the editor. Its tooltip
   reads **Use as default command-line Godot**.
2. Read the editor preferences explanation and select **Ok**.
3. If prompted, restart your terminal, then run:

   ```sh
   godot --version
   ```

The selected editor has a `godot` badge beside its name, and its terminal button
turns blue. The button shows a spinner while a change is in progress. Hover over
the selected button for a reminder of
how the command works. Godot Launcher can be closed while you use the command.

<ThemedImage

The restart reminder appears only when PATH setup changes. Switching editors
with unchanged setup updates the button without a success dialog. Conflicts and
errors are still shown.

The command forwards arguments to the selected editor. For example, run
`godot --headless --path /path/to/project --quit` with a build that supports
headless operation. Available command-line options depend on the selected build;
see the [Godot command-line tutorial](https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html).

On Windows, official installations use their console executable. For a custom
Windows build, register its console executable in the manifest's optional
`paths.console` field when it provides one. Otherwise the command uses the
registered editor executable, whose terminal capabilities depend on the build.

:::info Terminal editor preferences
Typing `godot` uses the selected editor's normal editor preferences. It does not
use the separate preferences Godot Launcher keeps for each project, such as editor
themes and shortcuts. Open the project from Godot Launcher to use its
[per-project editor preferences](./editor-settings.mdx). The project's own
configuration, including rendering and input settings, applies in either case.
Custom builds can also provide their own editor preferences configuration.
:::

### Switch or remove the command-line default

Select the terminal button on another installed editor to switch the command.
This changes the terminal default without changing the editor assigned to any
project. The previous default stays selected until the change succeeds.

To clear the default, select its blue terminal button again. Its tooltip reads
**Remove as default command-line Godot**. Removing the selected editor through
Godot Launcher also removes its command. The bin directory and PATH setup stay
in place so you can select a default again later without repeating setup.

If the selected editor's files become unavailable, the command reports an error.
It does not choose another version automatically. Restore the editor or choose
another installed editor as the default.

### PATH setup and command conflicts

Godot Launcher adds a fixed directory to your user PATH. The directory contains
the `godot` command, which points to the selected editor.

| Platform | Command directory |
| --- | --- |
| Windows | `%LOCALAPPDATA%\GodotLauncher\bin` |
| macOS | `~/Library/Application Support/GodotLauncher/bin` |
| Linux | `~/.local/share/godot-launcher/bin` |

On Windows, setup updates the user PATH. Close all windows of your terminal
application and reopen it if a new tab cannot find the command. If it still uses
the old PATH, sign out and sign in again.

On macOS and Linux, automatic setup supports Bash, Zsh, and Fish. Setup adds an
identifiable configuration block for Bash or Zsh, or a Fish configuration file.
For other shells, add the command directory to your PATH using that shell's
configuration. Quit Godot Launcher and start it from the configured terminal before
selecting the default, so it can read the updated PATH.

Existing commands keep their priority. If another `godot` command takes
precedence, the launcher reports it and preserves your command and PATH order.
Resolve the conflict in your shell or user PATH configuration, then restart your
terminal. You can inspect command lookup with `where.exe godot` on Windows,
`command -v godot` in Bash or Zsh, or `type -a godot` in Fish, which also shows
functions and aliases.

## Add a custom-built Godot editor

Open the **Custom Editor** menu in **Installs** to register a custom-built Godot editor:

- **Select manifest file**: register an existing `godotlauncher-editor-manifest.json`.
- **Create custom editor manifest**: enter the editor details and create the manifest in the launcher.

Custom editors appear in **Installs** with a **Custom** badge. See [Custom-Built Godot Editors](./custom-editors.mdx) for the full workflow.
